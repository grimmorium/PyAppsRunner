=====================================================================
SPECIFICATION FOR AN AI AGENT: XML-DRIVEN CONSOLE MENU IN PYTHON
=====================================================================

GOAL
----
Write a Python application that runs in the console (target Linux,
also tested on Windows) which does the following:
  * displays a text menu built from an XML configuration file,
  * allows navigation with keys:  a = up,  z = down,
    Enter = confirm,
  * supports multiple menu levels (folders / submenus),
  * runs Python scripts indicated in the XML (directory + file name),
  * defines a simple interface (contract) that an invoked script must
    fulfill so that control returns to the menu after it finishes.

GENERAL RULES (apply at every step)
-----------------------------------
  1. Only the Python standard library (>= 3.9). The only additional
     dependency: pytest (tests only).
  2. Works on Linux and Windows. Imports of platform-specific modules
     (termios, tty, msvcrt) must be done LAZILY - inside functions /
     classes intended for that platform, never at the level of a shared
     module. Tests must pass on both systems (platform-dependent tests
     are marked with pytest.mark.skipif).
  3. Logic separated from input/output (I/O). Keyboard, screen, script
     launching and "pause" are injected (dependency injection), so all
     logic is testable without a real terminal.
  4. Type hints everywhere, dataclass where convenient, no stateful
     global variables.
  5. Encoding: UTF-8 (XML file, console output). UI texts in English,
     collected in one module (menu_app/texts.py) as constants.
  6. WORK ORDER: for each step write the tests first, then the code.
     Do not move on to the next step until `python -m pytest -q` is
     fully green.
  7. Do not add features beyond the specification. If something is
     ambiguous, choose the simplest solution consistent with the
     "Assumptions" and record the decision in the README.

---------------------------------------------------------------------
STEP 0. ASSUMPTIONS AND DESIGN DECISIONS (already made - do not change)
---------------------------------------------------------------------
  * The "base directory" (base_dir) = the directory containing the main
    script main.py (Path(__file__).resolve().parent). All paths from the
    XML are relative to base_dir. It can be overridden with the
    --base-dir argument (needed in tests).
  * Menu navigation is cyclic: pressing "up" on the first entry goes to
    the last one and vice versa.
  * At the end of every list there is a system entry:
      - in the main menu:  "Exit"
      - in submenus:       "Back"
    System entries do not come from the XML.
  * Scripts are run IN THE SAME PROCESS (importlib), not as subprocesses.
    Reason: simple contract (a run function) and the ability to pass a
    context. A script error must not crash the menu.
  * After a script finishes, we return by default to the menu level from
    which it was launched. A script can request returning to the main
    menu via ctx.exit_to_root().
  * After a script finishes, the program shows "Press Enter to return
    to the menu" (so the user has time to read the result), unless the
    script set ctx.skip_pause = True.
  * Ctrl+C in the menu = clean program exit (exit code 0). Ctrl+C while
    a script is running = interrupt the script and return to the menu.

STEP 2. XML FORMAT, DATA MODEL AND PARSER (menu_app/config.py)
---------------------------------------------------------------------
Configuration file format:

  <?xml version="1.0" encoding="utf-8"?>
  <menu title="Main Menu">
    <item name="Greeting" dir="scripts/basic" file="hello.py"/>
    <folder name="Tools">
      <item name="Exit-to-root demo" dir="scripts/tools"
            file="exit_to_root_demo.py"/>
      <folder name="Advanced">
        <item name="Error test" dir="scripts/basic"
              file="error_demo.py"/>
      </folder>
    </folder>
  </menu>

Rules:
  * Root element: <menu>, the `title` attribute is optional (default
    "Main Menu").
  * <folder name="..."> may contain <folder> and <item> (arbitrary
    depth). An empty folder is allowed.
  * <item name="..." dir="..." file="..."/> - all three attributes are
    required and non-empty. An <item> element cannot have children.
  * Order in the XML = order in the menu.
  * `file` must end with ".py" (case-insensitive).
  * Unknown elements -> error. Unknown attributes -> ignored.

Model (dataclass, frozen):

  @dataclass(frozen=True)
  class ScriptItem:
      name: str
      directory: str      # value of the dir attribute (relative)
      file: str

  @dataclass(frozen=True)
  class Folder:
      name: str
      children: tuple["MenuNode", ...]   # MenuNode = Folder | ScriptItem

API:
  class ConfigError(Exception): ...        # clear English message
  def load_menu(xml_path: Path) -> Folder  # root; name = title
  def parse_menu(xml_text: str) -> Folder  # same from text (tests)

Errors (ConfigError) with a message containing the line number when
available: malformed XML (ParseError), wrong root element, missing
attribute, empty attribute, wrong file type, unknown element, XML file
does not exist.

Tests (tests/test_config.py), minimum:
  * valid simple file -> expected tree,
  * three-level nesting, order preserved,
  * default title, custom title,
  * empty folder allowed,
  * diacritics in names (Polish letters such as a, e, l...),
  * each error case from the list above -> ConfigError,
  * missing file -> ConfigError,
  * file="x.txt" -> ConfigError, file="X.PY" -> OK.

STEP 3. SCRIPT PATH RESOLUTION (menu_app/paths.py)
---------------------------------------------------------------------
  def resolve_script_path(base_dir: Path, item: ScriptItem) -> Path

Rules:
  * Replace "\" with "/" in `dir` (configuration portable across OSes).
  * `dir` must be relative (not absolute, no drive letter).
  * Result = (base_dir / dir / file).resolve().
  * The result must lie inside base_dir.resolve() (protection against
    "../../something"). Violation -> ConfigError.
  * Missing file or not a file -> ScriptNotFoundError
    (a subclass of Exception; the message contains the path).
  * File existence is checked at run time, not when reading the XML
    (the menu must work despite a missing script - the user gets a
    message after selecting the entry).

Tests (tests/test_paths.py): correct path, "\" separator, absolute path
-> error, "../outside" -> error, missing file -> ScriptNotFoundError,
directory instead of file -> ScriptNotFoundError.

STEP 4. SCRIPT CONTRACT AND RUNNER (script_api.py, runner.py)
---------------------------------------------------------------------
CONTRACT THAT EVERY INVOKED SCRIPT MUST FULFILL:

  1. It is an ordinary .py file containing a module-level function:

         def run(ctx) -> int | None:
             ...

  2. Return value:
       None or 0  -> success,
       any other integer -> error (the menu shows the code).
  3. Returning to the menu = simply finishing the run function (return).
     Also allowed: sys.exit(n) (treated as return n) and Ctrl+C
     (treated as cancellation).
  4. Module-level code (outside run) should do nothing (importing must
     be side-effect free).
  5. A script uses ordinary print() / input() - the terminal is in
     normal mode (the menu restores it before launching).
  6. A script may import modules lying next to it - the script's
     directory is added to sys.path for the duration of the run.
  7. A script does NOT change the process working directory.

ScriptContext (script_api.py), dataclass:

  base_dir: Path                  # application base directory
  script_path: Path               # full path of the file being run
  script_dir: Path                # script's directory
  menu_path: tuple[str, ...]      # e.g. ("Tools", "Advanced")
  skip_pause: bool = False        # True -> no "Press Enter..." pause
  exit_to_root_requested: bool = False  # set by the method

  def exit_to_root(self) -> None   # sets the flag; the script then returns
  def pause(self, message: str = texts.PRESS_ENTER) -> None
        # calls input(message); ignore EOFError

Runner (runner.py):

  @dataclass
  class RunResult:
      ok: bool
      return_code: int           # 0 = success
      error: str | None          # message for the user
      exit_to_root: bool
      skip_pause: bool

  def run_script(ctx: ScriptContext) -> RunResult

Behavior of run_script:
  * Loads the file via importlib.util.spec_from_file_location under a
    unique module name (e.g. "menu_script_<path hash>"). The module does
    NOT stay in sys.modules permanently (remove it in finally) - every
    run is a fresh execution of the file.
  * For the duration of the call, insert ctx.script_dir at the front of
    sys.path; restore sys.path to its pre-call state in finally.
  * Missing `run` function or not callable -> RunResult(ok=False,
    error="The script does not define a run(ctx) function").
  * Exception during import or in run -> print the traceback
    (traceback.print_exc()), return ok=False with a short message.
    Never propagate an exception (except KeyboardInterrupt - see below).
  * SystemExit(code): None->0, int->int, other->1; ok = (code == 0).
  * KeyboardInterrupt: catch it, print "Interrupted.", ok=True,
    return_code=130 is NOT an error - set ok=True, error=None.
  * A non-int returned value (other than None) -> treat as a contract
    violation: ok=False, message "run() should return int or None".
  * Copy ctx.exit_to_root_requested and ctx.skip_pause into RunResult.

Tests (tests/test_runner.py) on files created in tmp_path:
  * run returns None -> ok; returns 0 -> ok; returns 3 -> ok=False,
    return_code=3,
  * missing run function, run is not a function,
  * exception in run (RuntimeError) -> ok=False, the menu "survives",
  * exception at import time (SyntaxError, module-level error),
  * sys.exit(0), sys.exit(5), sys.exit("text"),
  * KeyboardInterrupt raised in run -> ok=True,
  * script calls ctx.exit_to_root() -> RunResult.exit_to_root=True,
  * script sets ctx.skip_pause=True -> copied over,
  * sys.path restored after the run (also after an error),
  * a script importing a neighboring helper module works,
  * two consecutive runs of the same file execute it from scratch
    (e.g. a counter in the file / a module variable is not preserved),
  * the script's stdout is visible (capsys).

STEP 5. NAVIGATION - MENU STATE WITHOUT I/O (menu_app/navigator.py)
---------------------------------------------------------------------
Pure logic, zero prints and zero key reads.

  class EntryKind(Enum): FOLDER, SCRIPT, BACK, EXIT

  @dataclass(frozen=True)
  class Entry:
      kind: EntryKind
      label: str
      node: MenuNode | None     # Folder or ScriptItem; None for BACK/EXIT

Actions returned by activate():
      @dataclass(frozen=True) class Stay: ...        # nothing happens
      @dataclass(frozen=True) class RunScript:
          item: ScriptItem
          menu_path: tuple[str, ...]
      @dataclass(frozen=True) class Quit: ...

  class Navigator:
      def __init__(self, root: Folder)
      def entries(self) -> list[Entry]       # children + BACK/EXIT at the end
      def selected_index(self) -> int
      def move_up(self) -> None              # cyclically
      def move_down(self) -> None            # cyclically
      def activate(self) -> Stay | RunScript | Quit
      def breadcrumb(self) -> tuple[str, ...]   # folder names without root
      def title(self) -> str                 # root's title
      def go_root(self) -> None              # reset to the main menu

Rules:
  * activate() on FOLDER: goes deeper, selection = 0, returns Stay.
  * activate() on BACK: goes one level up and RESTORES the selection
    that was there before entering the submenu; returns Stay.
  * activate() on EXIT: returns Quit.
  * activate() on SCRIPT: returns RunScript (navigation state does not
    change).
  * In root the last entry = EXIT, in submenus = BACK.
  * Empty folder: the list contains only BACK (selection 0).
  * go_root(): clears the stack, selection in root = 0.

Tests (tests/test_navigator.py): entering/leaving a folder, position
remembered after returning (at three levels), cyclic up and down, empty
folder, root with only EXIT, breadcrumb, go_root from a deep level,
RunScript carries the correct menu_path, Quit only from EXIT.

STEP 6. RENDERER (menu_app/renderer.py)
---------------------------------------------------------------------
A pure function building the screen text:

  def render_screen(title: str,
                    breadcrumb: tuple[str, ...],
                    labels: list[str],
                    selected: int,
                    width: int,
                    height: int) -> str

Screen layout (every line ends with "\n", no ANSI codes in the content,
so that tests stay simple):

  line 1: title  (or "title / folder / subfolder" when breadcrumb is
           non-empty)
  line 2: separator made of "-" characters, length min(width, 40)
  lines:  entries: "> label" for the selected one, "  label" for the
           rest
  line:   blank
  footer: "a - up | z - down | Enter - confirm"

Rules:
  * Viewport window: number of visible entries = max(1, height - 5)
    (header 2 + blank 1 + footer 1 + spare 1). The selected entry is
    ALWAYS visible. When part of the list is hidden, add "..." indicator
    rows at top/bottom ("  ...") (they count toward the height limit).
  * Lines longer than width are truncated to width-1 characters with an
    appended "...".
  * No exceptions for very small windows (width < 10, height < 6).

Tests (tests/test_renderer.py): selected row has the "> " prefix, only
one is selected, breadcrumb in the header, footer present, scrolling: a
list of 50 entries in a 10-line window - the selected one visible for
indices 0, 25, 49 and "..." indicators in the right places, truncation
of a long label, small window without exception, non-ASCII characters.

STEP 7. KEY READING (menu_app/keys.py)
---------------------------------------------------------------------
  class Key(Enum): UP, DOWN, ENTER, INTERRUPT, OTHER

  def map_char(ch: str) -> Key        # pure function
      "a","A"           -> UP
      "z","Z"           -> DOWN
      "\r","\n"         -> ENTER
      "\x03" (Ctrl+C)   -> INTERRUPT
      anything else     -> OTHER

  class KeyReader(Protocol):
      def read_key(self) -> Key

  class PosixKeyReader:
      read_key():
        - fd = sys.stdin.fileno(); save termios.tcgetattr(fd);
          tty.setcbreak(fd) (or setraw with Ctrl+C handled via "\x03");
          read one character (os.read(fd, 1) decoded as utf-8 with
          errors="ignore"); in finally ALWAYS restore the settings
          (termios.tcsetattr(fd, TCSADRAIN, old)).
        - Escape sequences (arrows: "\x1b[A") are ignored -> OTHER
          (swallow the rest of the sequence so it does not "leak").
        - EOF (empty read) -> INTERRUPT.
        - Import termios/tty inside the class/method.

  class WindowsKeyReader:
      read_key(): msvcrt.getwch(); if the character is "\x00" or "\xe0"
      (special keys) -> swallow the next character and return OTHER;
      "\x03" -> INTERRUPT. Import msvcrt inside the class/method.

  def create_key_reader() -> KeyReader   # chosen by os.name == "nt"

  class FakeKeyReader (in tests/ or in menu_app/testing.py):
      takes a list of Keys and returns them one after another; when
      exhausted raises AssertionError("no more keys") - protects the
      tests against an infinite loop.

Tests (tests/test_keys.py): map_char for all cases and a few random
characters; create_key_reader returns the right class (monkey-patching
os.name is not required - a platform-dependent test suffices); a
PosixKeyReader test on a pseudoterminal (stdlib `pty`: pty.openpty(),
swap sys.stdin with the slave, write "a", "z", "\r", "\x1b[A" from the
master side) - mark it @pytest.mark.skipif(os.name == "nt"); also check
that after read_key() the termios settings are restored.

STEP 8. APPLICATION MAIN LOOP (menu_app/app.py, terminal.py)
---------------------------------------------------------------------
terminal.py:
  def enable_ansi() -> None      # Windows: os.system("") or ctypes
                                 # (enabling VT); Linux: nothing
  def clear_screen(out) -> None  # out.write("\x1b[2J\x1b[H"); flush
  def get_size() -> tuple[int, int]   # shutil.get_terminal_size(
                                      #     fallback=(80, 24))

app.py:

  class App:
      def __init__(self, root: Folder, base_dir: Path,
                   key_reader: KeyReader, out: TextIO,
                   script_runner = run_script,
                   pause = input,
                   size_provider = get_size,
                   clear = clear_screen)
      def run(self) -> int          # returns the process exit code

Loop:
  1. navigator = Navigator(root)
  2. repeat:
       a) clear(out); out.write(render_screen(...)); flush
       b) key = key_reader.read_key()
       c) UP -> move_up; DOWN -> move_down; OTHER -> ignore;
          INTERRUPT -> return 0 (clean exit);
          ENTER -> action = navigator.activate():
             - Stay: continue,
             - Quit: return 0,
             - RunScript: perform the run procedure (below).
  3. Script run procedure:
       * clear(out)
       * path = resolve_script_path(base_dir, item); on
         ConfigError/ScriptNotFoundError print an error message and
         pause (the menu does NOT exit),
       * ctx = ScriptContext(...menu_path=action.menu_path...)
       * result = script_runner(ctx)
       * if not result.ok: print result.error and the code,
       * if not (result.skip_pause): pause(texts.PRESS_ENTER)
         (ignore EOFError from pause),
       * if result.exit_to_root: navigator.go_root().
  4. The terminal must be in normal mode after exit (guaranteed by
     PosixKeyReader - it restores the settings after every character).

Tests (tests/test_app.py) with FakeKeyReader, io.StringIO as out,
clear = lambda out: None, pause = lambda msg="": None, a stub
script_runner recording calls:
  * ENTER on "Exit" finishes with code 0,
  * [DOWN, ENTER] selects the second entry etc. (check that
    script_runner received the right file and menu_path),
  * entering a submenu, running a script, returning via "Back",
  * after a script we return to the same level and the same selection,
  * a script with exit_to_root -> the next screen is the main menu,
  * a script with an error (ok=False) -> error message on out, the menu works,
  * missing script file -> message and continued operation,
  * OTHER keys are ignored (screen unchanged),
  * INTERRUPT finishes with code 0,
  * skip_pause=True -> pause is not called; by default it is,
  * the screen contains entries from the XML (check on out.getvalue()).

STEP 9. ENTRY POINT (main.py)
---------------------------------------------------------------------
  def main(argv: list[str] | None = None,
           key_reader=None, out=None) -> int

Arguments (argparse):
    --config PATH     default <base_dir>/menu.xml
    --base-dir PATH   default the directory containing main.py

Behavior:
    * Windows: sys.stdout.reconfigure(encoding="utf-8",
      errors="replace") (if the method is available); enable_ansi().
    * ConfigError while reading the XML -> message on stderr,
      exit code 2.
    * When stdin is not a terminal (not sys.stdin.isatty()) and no
      key_reader was injected -> message on stderr, exit code 3.
    * Otherwise: App(...).run() and return its code.
    * At the bottom of the file:  if __name__ == "__main__": sys.exit(main())

Tests (tests/test_main.py): bad XML -> code 2 and a message on stderr
(capsys); missing configuration file -> code 2; --base-dir and --config
passed correctly; no TTY without an injected reader -> code 3; a valid
start with a fake reader [ENTER on "Exit"] -> code 0.
